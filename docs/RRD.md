**文档版本**：V1.0

## 一、产品概述

### 1.1 产品定位

通过AI视觉分析，帮助用户快速改善房间视觉整洁度，提供可立即执行的收纳建议，解决小空间杂乱痛点。

### 1.2 核心目标

- 用户拍照分析房间，获取简洁、可操作的整洁建议，快速提升房间观感
- 优先满足用户"视觉清爽"需求，后续扩展更多实用功能

### 1.3 用户群体

核心用户为18-35岁城市居民，空间有限、时间碎片化，希望通过低成本方式快速整理房间。

**用户分层**：

| 优先级 | 用户类型 | 核心场景 | 使用频率 | MVP优先 |
|--------|----------|----------|----------|---------|
| P0 | 租房青年 | 10-15㎡出租屋 | 日常整理（每周1-2次） | ✅ |
| P1 | 学生党 | 6-8㎡宿舍 | 日常整理 | ✅ |
| P2 | 家庭用户 | 卧室/客厅 | 周末整理 | 后续 |
| P3 | 搬家/迎客 | 任何房间 | 突击整理（低频刚需） | 后续 |

**MVP 聚焦**：10-15㎡出租屋 + 日常整理场景

## 二、用户需求与痛点分析

### 2.1 核心痛点

- 房间小、杂物多，视觉杂乱，缺乏整理动力或方法
- 希望快速见效，但传统收纳方法复杂耗时

### 2.2 用户目标

- 通过拍照获得即时分析，明确改进方向
- 建议简单（5分钟内完成）、零成本（利用现有物品）
- 肉眼可见的整洁效果提升

### 2.3 用户故事

**用户A（租房青年）**："每天下班回家看到乱糟糟的房间很烦躁，但不知道从哪里开始整理。如果拍张照片就能告诉我先处理哪堆东西，并且教我怎么用旧盒子改造，我会立刻尝试。"

**用户B（学生）**："衣服总是乱堆，但叠起来太麻烦。如果能快速学会卷叠法，或者知道哪些衣服需要熨烫，我会更有动力整理。"

## 三、功能需求

### 3.1 核心功能（MVP必做）

#### 3.1.1 拍照分析功能

**功能描述**：

- 用户拍摄房间照片（支持实时拍摄或相册上传）
- 照片临时传输至云端视觉模型进行分析，识别关键杂物（纸箱、散乱衣物、地面杂物等）
- 云端不持久化存储原图，分析完成后仅保留结构化结果（分数/杂物类型/建议）

**技术实现**：

采用 **云端视觉大模型 + 建议库匹配** 架构，调用火山引擎豆包 doubao-seed-2.0-pro（coding endpoint）的多模态能力完成图像理解（2026-08-02 从 mimo 切换，mimo 不可用，账号只买 coding 套餐）。

1. **图像采集**：App 调用摄像头/相册获取图片，压缩至 1024×1024 以内，转 Base64
2. **模型调用**：将图片 + 结构化 Prompt 发送至云端视觉模型 API
3. **Prompt 设计**：要求模型以 JSON 格式返回识别结果，包含物体类型、位置坐标（归一化 bounding box）、面积占比、置信度
4. **后处理**：解析 JSON，过滤置信度 < 0.6 的低质量识别，计算整洁度评分，匹配建议库
5. **结果展示**：前端在原图上绘制 bounding box 高亮问题区域，展示评分和建议

**模型输出格式（JSON Schema）**：

```json
{
  "scene": "bedroom|living_room|bathroom|desk",
  "clutter_items": [
    {
      "label": "cardboard_box|clothing|cable|book|bottle|food_container|shoe|other",
      "display_name": "纸箱",
      "count": 3,
      "bbox": [0.1, 0.2, 0.4, 0.6],
      "area_ratio": 0.18,
      "confidence": 0.92
    }
  ],
  "lighting": "bright|normal|dim",
  "overall_notes": "整体观察描述"
}
```

**输出结果**：

- 识别出杂物类型、数量、占比画面面积
- 高亮显示问题区域（如用边框标出纸箱堆）

#### 3.1.2 单维度评分系统

**功能描述**：

- 基于识别结果，计算"整洁度分"（0-100）
- 仅反映当前画面中杂乱物体的视觉占比
- 评分逻辑：杂物面积越小，分数越高

**评分公式**：

```
score = 100 - Σ(area_ratio_i × weight_i × 100) - lighting_penalty
```

| 参数 | 说明 | 取值 |
|------|------|------|
| `area_ratio_i` | 第 i 类杂物占画面面积比 | 0.0 ~ 1.0 |
| `weight_i` | 杂物类型视觉权重 | 见下表 |
| `lighting_penalty` | 光线不足惩罚分 | 0 或 5 |

**杂物类型权重**（视觉影响越大，权重越高）：

| 杂物类型 | 权重 | 说明 |
|----------|------|------|
| clothing（衣物） | 1.2 | 视觉面积大，颜色杂乱 |
| cardboard_box（纸箱） | 1.5 | 体积大，遮挡严重 |
| food_container（外卖/食物） | 1.3 | 卫生问题叠加视觉污染 |
| trash（垃圾） | 1.4 | 明显脏乱 |
| cable（电线） | 0.8 | 面积小但视觉焦虑感强 |
| book（书籍） | 0.7 | 视觉压迫感 |
| bottle（瓶罐） | 0.6 | 体积小 |
| shoe（鞋子） | 0.7 | 地面占用 |
| pillow_blanket（被褥） | 1.0 | 床面视觉焦点 |
| other_clutter（其他） | 1.0 | 默认权重 |

**边界情况**：
- 无任何杂物识别 → 100 分（满分）
- 所有杂物面积占比 > 80% → 最低 5 分（不给 0 分，留改进希望）
- 光线为 `dim` 时额外扣 5 分（光线差会放大杂乱感）

**关键价值**：直观展示改进空间，激励用户行动

#### 3.1.3 快速行动建议

**功能描述**：

- 针对每个识别出的问题，提供1条必做建议 + 1条备选建议
- 满足5分钟内可完成、零成本、立即可见效果
- 建议附15秒内短视频教程，存储本地可离线播放
- 提供用户纠错机制：识别不准时用户可从10个场景中手动选择（详见识别特征标签体系.md 置信度与纠错机制）

**示例**：

- **问题**：检测到3个纸箱（占画面42%）
- **建议**：
    - 必做："压扁纸箱，用胶带粘成窄条，插入抽屉分隔杂物"（附视频）
    - 备选："若空间允许，用纸箱搭简易书架"（附示意图）

### 3.2 扩展功能（后续迭代）

- 出行物品清单（可结合LBS提醒携带）
- 房间风格推荐（基于房间布局分析，推荐装饰方案）
- 社区分享：用户上传整理前后对比图，激励互动

## 四、非功能需求

### 4.1 性能要求

- 拍照分析延迟 ≤ 5秒（含云端模型调用）
- 视频加载流畅，支持离线播放

### 4.2 安全与隐私

- 用户照片默认存储在本地设备，分析时临时传输至云端模型进行处理，处理完成后云端不保留原图
- 分析结果脱敏后可选同步云端，用于历史记录和趋势追踪
- 用户可随时清除本地照片和历史记录
- 用户数据加密存储

### 4.3 可用性

- 界面简洁，操作流程不超过3步
- 无障碍设计：支持语音播报建议

### 4.4 兼容性

- 适配主流Android/iOS设备
- 摄像头权限管理明确

## 五、技术架构

### 5.1 前端

- 原生开发（React Native/Flutter），支持双端
- 摄像头调用、本地图像处理库集成

### 5.2 后端（轻量）

- 仅处理用户报错反馈和统计
- 使用阿里云轻量级服务（如函数计算FC）

### 5.3 AI能力

- 云端视觉大模型：doubao-seed-2.0-pro（火山引擎 Ark coding endpoint，2026-08-02 切换）
- 复用用户已有订阅额度，无需额外开通API
- 模型以多模态理解方式分析房间图片，输出结构化杂物识别结果（JSON）
- 后续可针对房间杂物场景进行 Prompt 优化或模型微调

### 5.4 数据存储

| 数据类型 | 存储位置 | 保留策略 |
|----------|----------|----------|
| 建议库、短视频教程 | App 内置 / 本地缓存 | 永久，支持离线 |
| 分析结果（分数/杂物/建议） | 本地 SQLite + 可选云端同步 | 永久，用于历史记录 |
| 用户照片 | 用户手机本地 | 用户可控删除，不上传云端 |
| 云端分析临时图片 | 云端内存 | 分析完成后立即丢弃，不持久化 |

## 六、开发计划

### 6.1 MVP阶段（12周）

| 阶段 | 时间 | 内容 |
|------|------|------|
| 需求确认+设计 | 第1-2周 | PRD定稿、UI/UX原型、技术选型、Prompt调试 |
| 核心开发 | 第3-8周 | 拍照分析、评分、建议匹配、历史记录、短视频集成 |
| 内测+灰度 | 第9-10周 | 种子用户测试（20-50人）、Bug修复、建议库校准 |
| 正式上线 | 第11-12周 | 应用商店上架、运营数据看板搭建 |

**MVP 交付范围**：
- 完成拍照分析、评分、基础建议功能（支持10类杂物）
- 集成10个场景共20条建议及对应短视频
- 用户纠错机制（10场景手动选择）
- 历史记录（分数趋势 + 前后对比）
- 完成隐私保护和性能优化

### 6.2 V1.1阶段（上线后3个月）

- 增加识别类别（电线杂乱、书籍堆放等）
- 支持用户自定义房间类型，优化建议针对性
- 上线出行清单功能
- 每场景建议扩充到3-5条，支持轮换展示

### 6.3 长期迭代

- 引入AR模拟（展示整理后的房间效果）
- 社区与激励机制（积分、成就系统）
- 品牌合作模块（独立于建议库，标注"广告"）

## 七、验收标准

### 7.1 功能测试

- 拍照分析准确率≥85%（针对10类杂物）
- 建议执行后，用户二次拍照评分提升≥15分
- 用户纠错流程可用：点击"不准"→展示10个场景→选择后匹配建议

### 7.2 用户体验

- 用户完成首次整理流程耗时 ≤ 8分钟
- 95%用户能无障碍完成建议操作
- 建议文案口语化，无书面语

### 7.3 性能指标

- App启动时间 ≤ 2秒
- 拍照分析延迟 ≤ 5秒（含云端模型调用）
- 本地存储占用 ≤ 200MB（含建议库和短视频）

## 八、数据埋点与运营指标

### 8.1 核心埋点

| 埋点事件 | 触发时机 | 采集字段 |
|----------|----------|----------|
| `photo_taken` | 用户拍照/上传图片 | 图片来源（相机/相册）、时间戳 |
| `analysis_complete` | 分析返回结果 | 评分、识别到的杂物类型列表、置信度 |
| `suggestion_viewed` | 用户查看建议 | 场景ID、建议类型（必做/备选） |
| `suggestion_executed` | 用户标记"已完成" | 场景ID、执行耗时 |
| `error_reported` | 用户点击"不准" | 原始识别结果、用户选择的正确场景 |
| `retake_photo` | 用户二次拍照 | 前后评分差值 |

### 8.2 北极星指标

| 指标 | 定义 | MVP 目标 |
|------|------|----------|
| 建议执行率 | 查看建议后标记"已完成"的比例 | ≥ 30% |
| 二次拍照率 | 执行建议后再次拍照验证的比例 | ≥ 20% |
| 评分提升幅度 | 执行建议前后的平均分差 | ≥ 15分 |
| 7日留存率 | 首次使用后7天内再次使用的比例 | ≥ 25% |
| 纠错率 | 触发"不准"的比例（越低越好） | ≤ 15% |

## 九、风险与应对

### 9.1 AI识别不准确

**解决方案**：提供用户纠错机制（10场景手动选择），收集纠错数据迭代Prompt；低置信度结果fallback到兜底建议

### 9.2 用户执行建议后效果不显著

**解决方案**：严格限制建议为"立竿见影"型，避免复杂操作

### 9.3 隐私合规风险

**解决方案**：明确隐私政策，云端不持久化存储原图，分析结果脱敏后可选同步
